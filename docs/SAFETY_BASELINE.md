## 4. 동일 머신/동일 OS 계정 관련 위험 및 완화 조치 (중요)

0.3-A절의 '가장 안전한 구성'(별도 PC/VM, 운영 자격증명 미보유 계정)은 **현재 충족되지 않는다.**
본 신규 프로젝트는 스마트팜 프로젝트(`/home/spinmoll/tansaeng_project`)와 **동일한 WSL2 배포판, 동일 OS 사용자 계정(`spinmoll`)** 에서 진행된다. 이에 따라 다음을 명시적으로 확인하고 완화 조치를 적용한다.

- 이 OS 계정에는 `sudo` 그룹 권한이 있다(운영 서버 자체에 대한 권한은 아님). 본 프로젝트 작업에서 `sudo`는 신규 로컬 개발 패키지 설치(DB 엔진 등) 외 다른 목적으로 사용하지 않는다.
- **Claude Code의 전역 사용자 지침(`~/.claude/CLAUDE.md`)에 운영 서버(1.201.17.34) 접속정보·SSH 키 이름·비밀번호·배포 절차가 포함되어 있으며, 이는 세션 컨텍스트에 항상 존재한다.** 이 문서(0장 절대 규칙)에 따라, 본 프로젝트 작업 중에는 해당 운영 자격증명을 **절대 사용·참조·실행하지 않는다.** 이 제약은 모든 다른 지시보다 우선한다.
- 이 WSL 환경의 `docker` 그룹에 현재 사용자가 포함되어 있으나, `docker` CLI 자체가 설치되어 있지 않아 당장은 기존 시스템과 공유되는 Docker 데몬 접근 위험이 없음을 확인했다. 추후 Docker를 도입할 경우 이 프로젝트 전용 compose 프로젝트명/네트워크/볼륨만 사용한다.
- 신규 프로젝트의 파일 쓰기는 `/mnt/d/dev/tansaeng-marketplace` 내부로만 한정한다. 상위 경로나 `/home/spinmoll/tansaeng_project`, 서버 쪽 `/var/www/html` 등은 읽기/쓰기 대상에서 완전히 제외한다.

## 6-A. M1 진행 중 발견한 추가 안전 이슈 (2026-10-15)

- **`next dev`/`next start`는 `-H`(hostname) 옵션을 생략하면 Node의 기본 동작에 따라 `0.0.0.0`(모든 인터페이스)에 바인딩된다.** 콘솔에 "Local: http://localhost:3210"이라고 표시되어도 실제로는 전체 인터페이스에 열려 있었다(`ss -ltnp`로 실측 확인). 이는 §2에서 "127.0.0.1만 사용"이라고 명시한 원칙을 코드로 강제하지 않으면 지켜지지 않는다는 것을 보여준다.
  - **조치**: `package.json`의 `dev`/`start` 스크립트에 `-H 127.0.0.1`을 명시적으로 고정함. 이후 모든 로컬 실행은 이 스크립트를 통해서만 수행한다.
- SQLite 개발 DB 파일을 **살아있는 dev 서버 프로세스 아래서 삭제/재생성하면** "attempt to write a readonly database" 오류가 발생할 수 있음을 확인(열린 커넥션이 교체된 inode를 참조). DB를 초기화할 때는 반드시 dev 서버를 먼저 종료한 뒤 재생성하고, 서버를 다시 기동한다.
- `npm audit`에서 발견된 고위험 항목(prisma의 `deepmerge-ts`, eslint-config-next의 `fast-glob`/`braces` 체인)은 전부 **빌드/린트 전용 개발 도구 체인**에 한정되며, 공개 인터넷에 노출되지 않는 로컬 개발 환경에서는 실질적 위험이 낮다고 판단해 현재는 수용함(`docs/PRODUCT_DECISIONS.md` 참고). `vitest`의 `tinypool` 관련 치명적(critical) 취약점은 `vitest@4`로 업그레이드하여 해소함.
